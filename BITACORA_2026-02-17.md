## Contexto inicial

El módulo **Ranking** en Cognitive Tasks no funcionaba correctamente: mostraba un selector genérico en vez del editor de items. Además, había una serie de problemas derivados de la arquitectura de media y configuración que se fueron descubriendo durante las pruebas.

## 1. Fix del módulo Ranking en research-frontend

**Commits:** `eb56965`, `334a873`

**Problema:** El seed template definía el componente de items como `type: 'ranking-list'`, pero `EditableComponent.tsx` solo tenía `case 'ranking'` en el switch. El tipo `ranking-list` caía al default y se renderizaba como un select genérico.

**Cambios:**
- `research-frontend/src/types/moduleBuilder.types.ts` — Agregado `'ranking-list'` a la union `ComponentType`
- `research-frontend/src/components/research/EditableComponent.tsx`:
  - Extraído `RankingItemsEditor` como componente standalone (antes estaba definido inline dentro del case, causando re-mount en cada re-render del parent — anti-patrón de React)
  - Agregado `case 'ranking-list':` que cae al mismo `RankingItemsEditor`

**Migración en BD:** Se ejecutó `fix_ranking_module_config_mysql.ts` en producción vía SSH a cPanel. 24 de 25 módulos Ranking corregidos con la estructura correcta (`ranking-list` en vez de componentes genéricos).

**Fix adicional:** El script de migración tenía el path de dotenv incorrecto (`../../.env` → `../.env`) para la estructura de directorios en cPanel.

## 2. Fix de módulos que se ocultaban automáticamente al guardar

**Commit:** `513bb28`

**Problema:** Al guardar en Cognitive Tasks, el código calculaba `finalHidden = !hasModuleConfiguredValues(...)`. Esto marcaba como `hidden: true` cualquier módulo sin datos, impidiendo que el investigador pudiera editarlo después. Los módulos Navigation Flow y Preference Test quedaban en blanco con solo su nombre visible.

**Cambios:**
- `research-frontend/src/pages/research/ResearchBuilderPage.tsx` — El save ahora usa `moduleRef.getHidden()` (el valor explícito del toggle Hide del investigador) en vez de auto-calcular. Aplica tanto para Smart VOC como Cognitive Tasks.
- `research-frontend/src/components/research/CognitiveTaskModuleCard.tsx` — Removida restricción `isLocalhost()` del toggle Hide (era invisible en producción).
- `research-frontend/src/components/research/SmartVOCModuleCard.tsx` — Mismo fix del toggle Hide.

**Migración en BD:** Se corrigió `hidden: false` en Navigation Flow, Preference Test y 1 módulo adicional que tenían `hidden: true` por el auto-cálculo anterior. También se corrigió el config del módulo Ranking de "Clemente probando" (removido `image-upload`, agregado `question-description` para consistencia con los demás módulos).

## 3. Fix de resolución de URLs de media (research-frontend)

**Commit:** `513bb28`

**Problema:** El backend devuelve URLs de media como rutas relativas (`/api/media/research/{id}/{file}`). Cuando el frontend corre en `localhost:12800`, el browser resuelve esas URLs contra `localhost:12800` en vez de `emotio.cx`, causando 404.

**Cambios:**
- `research-frontend/src/services/media.service.ts` — Agregada función `resolveMediaUrl()` que convierte URLs relativas a absolutas usando el origen del API base URL. Se aplica en `generateUploadUrl`, `getMediaUrl` y `getMediaUrlByS3Key`.
- `research-frontend/src/components/ui/FileUploadAdvanced.tsx` — Limpiado el fix temporal que se había puesto inline.

## 4. Fix de re-mount del FileUploadEditor

**Commit:** `513bb28`

**Problema:** Al escribir en un textarea de Navigation Flow o Preference Test, los componentes de imagen se recargaban/parpadeaban con cada caracter. Causado por el mismo anti-patrón del Ranking: `FileUploadEditor` estaba definido como función inline dentro del `case 'file-upload'` del switch.

**Cambios:**
- `research-frontend/src/components/research/EditableComponent.tsx` — Extraído `FileUploadEditorComponent` como componente standalone definido fuera del render. React mantiene la misma instancia entre re-renders, preservando el estado de los archivos.
- El default case del switch ahora retorna `null` silenciosamente (en vez de mostrar "Component type X is not supported for editing").

## 5. Fix del participant-frontend: sync-runtime-config

**Commit:** `12be6c5`

**Problema:** `npm run dev` fallaba porque el script `sync-runtime-config.mjs` intentaba descargar `runtime-config.json` desde CloudFront de AWS (`d2am10cly7c9kf.cloudfront.net`), que ya no existe tras la migración a cPanel.

**Cambios:**
- `participant-frontend/scripts/sync-runtime-config.mjs` — URL default cambiada de CloudFront a `https://emotio.cx/participant`.

## 6. Fix del participant-frontend: config service en dev mode

**Commit:** `e27c51c`

**Problema:** Al abrir `localhost:12600/research/{id}?preview=true`, aparecía "Initialization failed — This build is configured to always use the AWS backend". El config service buscaba `runtime-config.json` en `/participant/runtime-config.json`, pero Vite sirve `public/` en la raíz (`/runtime-config.json`).

**Cambios:**
- `participant-frontend/src/services/config.service.ts`:
  - Default API URL cambiado de `localhost:3000` a `https://emotio.cx/api`
  - En dev mode, busca primero `/runtime-config.json`, luego `/participant/runtime-config.json`, con fallback al default
- `participant-frontend/src/components/BootstrapErrorScreen.tsx` — Removida referencia obsoleta a "AWS backend".

---

## 7. Fix del participant-frontend: resolución de URLs de media

**Commit:** `af65c4e`

**Problema:** Las imágenes de Navigation Flow y Preference Test no cargaban en el participant-frontend en modo local. Mismo problema que en research-frontend: URLs relativas resueltas contra localhost.

**Cambios:**
- `participant-frontend/src/services/media.service.ts` — Agregada función `resolveMediaUrl()` (idéntica a la del research-frontend). Se aplica al resultado de `getMediaUrl()` antes de cachearlo.
